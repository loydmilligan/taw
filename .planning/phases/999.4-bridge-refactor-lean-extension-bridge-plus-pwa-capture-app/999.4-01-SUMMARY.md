# Phase 999.4 Plan 01: Extract auth.ts + http-utils.ts Summary

Extracted auth utilities and HTTP primitives from the 3,046-line server.ts into two focused modules with full test coverage, adding a 1 MB body cap security constraint.

## What Was Built

**src/bridge/auth.ts** — all cookie session and token auth functions extracted verbatim from server.ts, plus the appSessions Map. Exports: `authorize`, `authorizeApp`, `createAppSession`, `ensureAppState`, `setAppSessionCookie`, `getAppSessionRecord`, `getAppSessionId`, `parseCookies`, `cleanupOldAppSessions`, `appSessions`.

**src/bridge/http-utils.ts** — HTTP request/response helpers extracted from server.ts. Added 1 MB body cap to `readJson` per T-999.4-01 threat mitigation. Exports: `parseRequestUrl`, `readJson`, `writeJson`.

**src/bridge/server.ts** — now imports from both new modules; 134 lines removed (inline function bodies and appSessions Map declaration).

## Test Coverage

- auth.test.ts: 13 tests covering authorize, authorizeApp, parseCookies, setAppSessionCookie, getAppSessionRecord, cleanupOldAppSessions
- http-utils.test.ts: 9 tests covering parseRequestUrl, readJson (including 1 MB cap rejection), writeJson

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] randomUUID still needed in server.ts**
- **Found during:** Task 3 (build verification)
- **Issue:** server.ts uses randomUUID for background job IDs; the import was removed when stripping auth imports
- **Fix:** Re-added `import { randomUUID } from 'node:crypto'` to server.ts
- **Files modified:** src/bridge/server.ts
- **Commit:** 32853a2

**2. [Rule 2 - Missing] parseCookies handles undefined input**
- **Found during:** Task 1 implementation
- **Issue:** Original server.ts parseCookies only accepted string; callers pass `request.headers.cookie` which can be undefined
- **Fix:** Changed signature to `string | undefined`; added early return `{}` for falsy input
- **Files modified:** src/bridge/auth.ts
- **Commit:** 6d87a44
